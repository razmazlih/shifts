# תהליכי העבודה החדשים — שלב א׳

המסמך מתאר את ענף העבודה המקומי. אין בכך אישור לפריסה או למיגרציה בייצור.

## מנהל

- ברירת המחדל היא רשימה קריאה. אפשר לעבור לציר זמן; רק העדפת התצוגה נשמרת בדפדפן.
- ״לטיפול״ מציג את הבעיה, היום, השעות ומשמרת המקור. חוסר מחושב בכל מקטע זמן לפי עובדים ייחודיים. אפשר לפתוח משמרת או לבדוק מועמד מתאים.
- ״שיבוץ חכם״ דורש בחירת ימים וצוותים שאינה תלויה במסנני התצוגה. ״השלמת חוסרים״ שומרת את השיבוצים הקיימים. ״תיקון שיבוצים״ מאפשר הצעות לשינוי בלבד.
- ההצעה נשמרת בנפרד ל־30 דקות. ביטול לא משנה את הטיוטה. ״החלה על הטיוטה״ שומרת בדיוק את ההצעה, לאחר בדיקת הרשאות, גרסה, עובדים, אילוצים והתחייבויות בשבועות שכנים. הצעה שהתיישנה נדחית.
- אפשר לנעול שיבוץ בחלונית המשמרת. האוטומציה מכבדת את הנעילה; סתירה לכלל נשארת גלויה וחוסמת פרסום.
- לפני פרסום מוצגים השינויים מהפרסום הקודם, העובדים המושפעים, החוסרים והשגיאות. חוסר דורש אישור מפורש שנרשם בהיסטוריה. שגיאות חוסמות גם API ישיר. הפרסום נבדק שוב בטרנזקציה.
- הפצה והדפסה משתמשות בפרסום כברירת מחדל. אפשר לבחור טיוטה המסומנת בבירור. שמירה שנכשלה משאירה את הקלט ומציגה ״לא נשמר״.

## עובד

הכניסה מציגה משמרת נוכחית או הבאה מתוך הפרסומים בלבד, גם מעבר לשבוע הנוכחי. לילה מציין במפורש את יום הסיום. מתחת מופיעה רשימה כרונולוגית וגישה ללוח הצוות ולסיכום החודשי. סיכומי שעות מתארים שיבוץ מתוכנן, לא נוכחות או שכר.

## נתונים ואימות

המיגרציה `20261106000000_schedule_proposals` מוסיפה טבלת הצעות בלבד. הנעילות נשמרות בשיבוצי JSON עם שדה אופציונלי, ללא מחיקת נתונים ישנים.

שלב א׳ נבדק ב־6 בנובמבר 2026: 112 בדיקות יחידה, 36 בדיקות E2E לאורך הרצה סדרתית וריצות תיקון, lint, typecheck ו־build. נעשה שימוש ב־PostgreSQL מקומי נפרד עם מידע פיקטיבי, ובשרת standalone מקומי. נבדקו 360/390/768/1440, שבוע ריק ועמוס, שמות ארוכים ולילה. צילומים נבדקו חזותית. לא נבדקו מכשיר פיזי, Safari או Firefox.

אפשר להריץ E2E סדרתית במסד מקומי ששמו מסתיים ב־`_test`:

```bash
TEST_DATABASE_URL='postgresql://USER@127.0.0.1:PORT/NAME_test' \
BASE_URL=http://localhost:3336 npm run test:e2e:local
```

הכלי מנקה רק מוני התחברות במסד הבדיקות בין קובצי הבדיקות. מנגנון ההגבלה של המוצר נשאר פעיל. `NEXT_DIST_DIR=.next/review-build` מאפשר build ו־start נפרדים משרת פיתוח קיים. יש להגדיר `DATABASE_URL`, `APP_URL` ו־`PORT` בהתאם למסד ולשרת הבדיקות.

שלב ב׳ יתווסף לאחר שער האימות של שלב א׳. לא הוגדר שירות חיצוני בתשלום ולא נעשתה פריסה לייצור.
